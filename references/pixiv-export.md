# pixiv小説エクスポート（pixiv Export）

本プロジェクトの `novel/` を **pixiv小説** に投稿するための標準変換手順。実装は `scripts/pixiv_export.py`。

---

## 設計原則

| # | 原則 | 意味 |
|---|------|------|
| 1 | **Pure Conversion** | 本文（地の文・台詞・擬音）は改変しない。記法のみ変換する |
| 2 | **Reproducibility** | 同じソースから同じ出力を得られる（決定論的） |
| 3 | **Non-destructive** | `novel/` 配下のソースファイルを変更しない |
| 4 | **Metadata Separation** | pixiv固有のメタデータ（タイトル・あらすじ・タグ・R-18）は本文と分離する |
| 5 | **Upstream Fix** | 変換時の矛盾（重複・誤字等）はソース側で修正する。スクリプトで隠蔽しない |

## pixiv小説の仕様制約

| 項目 | 制約 |
|------|------|
| 投稿字数 | 最大 **50,000字 / 1投稿**（超過時はシリーズ分割） |
| ルビ記法 | `｜漢字《るび》` |
| 挿絵 | pixivエディタで別途挿入（本文中はプレースホルダーのみ） |
| R-18指定 | 投稿時に pixiv 側で設定（本文に書かない） |
| 見出しレベル | `## `（h2）推奨。`# `（h1）はpixivのタイトル欄と衝突するため本文では使用しない |
| 改行 | 1行空ける（pixiv推奨） |

## ファイル構造

```
project_root/
├── proposal.md              # 企画書（ヘッダーのタイトル・あらすじ取得元）
├── meta.toml                # 章の目次
├── character/               # 既存（参照のみ）
├── worldbuilding/           # 既存（参照のみ）
├── plot/                    # 既存（参照のみ）
├── novel/                   # ソース（変換元。絶対に変更しない）
│   ├── ch01.md
│   ├── ch02.md
│   └── ...
├── export/                  # 出力先（スクリプトが自動作成）
│   └── pixiv.md             # pixiv投稿用完成版
└── .context/                # pack生成物（変換では使わない）
```

### ソースファイル名の規約

標準は `novel/chNN.md`（2桁以上）。旧形式 `{連番}-{章タイトル}.md`（例: `01-第一章_覚醒.md`）も後方互換で受理するが、新規は `chNN.md` に統一する。

- 章順はファイル名の番号の昇順（`meta.toml` の記述順ではない）
- 規約に合わない `.md` は `[WARN]` でスキップされる（エラー停止しない。混入に注意）
- `chNN.md` にH1/H2見出しがない場合、タイトルは `第N章` の自動補完になる。このとき出力見出しは `## 第1章　第1章` と重複する。**`novel/chNN.md` の先頭には `# 章タイトル` を置くこと**（Upstream Fix。check_prose.py の章見出し検査と併用）

## 変換ステップ

### Step 1: ソース読込

`novel/` 配下の `.md` を番号順に読む。本文先頭のH1/H2行があれば章タイトルとして優先し、本文からは除去する（pixiv用に `## 第N章` で再付与するため）。

### Step 2: 記法変換

#### 2-1. ルビ記法

| 入力形式 | 出力形式 | 扱い |
|---------|---------|------|
| `｜漢字《るび》` | `｜漢字《るび》` | 変換不要（pixiv記法のまま） |
| `{漢字\|るび}` | `｜漢字《るび》` | 自動変換 |
| `[[rb: 漢字 > るび]]` | `｜漢字《るび》` | 自動変換 |

JIS式の `《るび》漢字` は自動変換しない（誤検知リスク）。使う場合は手動でpixiv記法に直す。

#### 2-2. 画像プレースホルダー

| 入力形式 | 出力形式 |
|---------|---------|
| `![alt](URL)` / `![img](file.png)` | `[※挿絵N]`（通番） |
| `[[image:N]]` | `[※挿絵N]`（通番。元のNは引き継がない） |
| `（※挿絵）` / `※挿絵` | `[※挿絵N]`（通番） |

内部では NUL マーカーで一旦切り出してから最終形に戻すため、変換済みプレースホルダーの再マッチは起きない。ただしソース側に `[※挿絵N]` を**手書きしないこと**（`※挿絵` 部分が再マッチして崩れる）。挿絵位置の指定は `![...](...)` か `<!-- 挿絵: シーン説明 -->` のコメントで行う。

#### 2-3. 章見出し

`## 第{order}章　{title}` で再付与する。**サブタイトル等を独自に追加しない**。タイトルを変えたい場合は `novel/chNN.md` 先頭のH1を編集する。

#### 2-4. 改行・空行の正規化

連続3つ以上の改行を2つに統一し、末尾改行を確保する。`---`（HR）は除去しない。本文側の `---` は変換後も水平線として残るため、要らないものはソース側で消す（Upstream Fix）。

### Step 3: ヘッダー・フッター生成

タイトル・あらすじ・タグは投稿画面で別途入力する。本文中には **HTMLコメント** として引き継ぎメモを付けるだけに留める（pixivレンダラはHTMLコメントを無視する）。

#### 3-1. ヘッダー（ファイル先頭）

```html
<!--
pixiv設定メモ（投稿時に pixiv 側で入力）
==========================================
タイトル: <proposal.md の ## タイトル から取得>
あらすじ: <proposal.md の ## 概要 から取得>
R-18:    <proposal.md の ## R-18 から取得>
文字数:   <変換後の文字数>
挿絵数:   <プレースホルダー数>
==========================================
-->
```

> **注意**: `scripts/init.py` の proposal 雛形には `## タイトル` / `## 概要` / `## R-18` セクションがない。そのままではヘッダーが「（タイトル未設定 — proposal.md を確認）」になる。pixiv投稿する作品ではこの3セクションを proposal.md に足しておく。

#### 3-2. フッター（ファイル末尾）

```html
---

<!--
変換ログ
==========================================
ソース:    <novel/*.md ファイル一覧>
章数:     <N章>
変換日時: <YYYY-MM-DD HH:MM>
変換者:    pixiv_export.py v1.0.0
==========================================
このフッターは pixiv 投稿時に削除してください。
-->
```

### Step 4: 出力

`export/pixiv.md` に統合出力する。`novel/` は変更しない。

## 実行スクリプト

```bash
# 単一ファイルに統合（export/pixiv.md）
python scripts/pixiv_export.py --project-dir <project>

# novel/ 以外を入力にする場合
python scripts/pixiv_export.py --input-dir <novel_dir> --output <out.md>

# 50,000字超過時に章分割（export/pixiv_01.md, pixiv_02.md, ...）
python scripts/pixiv_export.py --project-dir <project> --split

# 差分検証のみ（変換しない。出力ファイルが存在すること）
python scripts/pixiv_export.py --project-dir <project> --verify

# 文字数チェックのみ（変換しない。超過時は exit 1）
python scripts/pixiv_export.py --project-dir <project> --check-length
```

### 変換チェックリスト

変換後、以下を確認する：

- [ ] **本文差分なし** — `--verify` が `[OK]`（見出し・コメント・プレースホルダー・ルビを正規化して比較する）
- [ ] **ルビ統一** — `grep -E "\{[^|}]*\|" export/pixiv.md` が 0 件
- [ ] **画像プレースホルダー** — `grep -c "※挿絵" export/pixiv.md` が期待値と一致
- [ ] **章見出し連番** — `grep -E "^## 第[0-9]+章" export/pixiv.md` が章数と一致
- [ ] **字数制限** — `--check-length` が OK（コメント除く本文で 50,000 字以内）
- [ ] **H1不在** — `grep -E "^# [^#]" export/pixiv.md` が 0 件

> **注意**: `--verify` の novel 側正規化は `![...](...)` 形式の画像タグのみ除去する。`[[image:N]]` や `（※挿絵）` をソースに使っている場合、export 側では除去されるのに novel 側では残るため差分扱いになる。検証を通したい章の画像指定は `![...](...)` に統一するか、差分の原因が画像タグのみであることを目視確認する。

## pixiv投稿時の追加作業

1. **タイトル・あらすじ** — 投稿画面で `<!-- pixiv設定メモ -->` の内容を転記
2. **R-18設定** — R-18タグと年齢確認をチェック
3. **タグ設定** — 5〜10個を推奨（必須タグ＝内容直結／集客タグ＝検索されやすい語／R-18タグ＝公式体系に従う）。自動選定はしない
4. **挿絵のアップロード** — `[※挿絵N]` の位置に pixiv エディタで画像をアップロード（作成手順は `illustration-guide.md`）
5. **フッター削除** — ファイル末尾の `<!-- 変換ログ -->` を削除
6. **プレビュー** — スマホ・PC両方の表示で確認

## シリーズ投稿への拡張

50,000字超は `--split` で章単位に分割する。出力は `export/pixiv_01.md`、`pixiv_02.md`、…。各ファイルにヘッダー・フッターが付く。タイトル・あらすじは第1話に集約し、pixivのシリーズ機能を使う。

超過時の動作は警告のみ（分割の強制や `--force` はない）。分割するかどうかは人間が決める。

## エラーハンドリング

| 状況 | 対応 |
|------|------|
| 50,000字超過 | `[WARN]` のみ。`--split` で分割を検討 |
| 章ファイルに見出しがない | ファイル名由来のタイトル（chNNなら `第N章`）を使用。重複見出しに注意 |
| ルビ記法の混在 | すべて pixiv 記法に統一 |
| 画像プレースホルダーが極端に多い（章あたり 20+） | 警告は出ない。pixivの1投稿あたり推奨は10枚以下なので人間が判断 |
| 規約外の `.md` が `novel/` にある | `[WARN]` でスキップ（停止しない） |
| `novel/` ディレクトリが存在しない | エラー終了 |
| ソースファイルが 0 件 | エラー終了 |

## 実装時の落とし穴（Pitfalls）

`pixiv_export.py` を改造・再実装する際に実際に踏んだバグの記録。次のセッションで同じ罠を踏まないために：

### Pitfall 1: 画像プレースホルダーの再マッチバグ

```python
# NG: re.sub を二回呼ぶとプレースホルダーが再マッチされる
# OK: 内部マーカー（NUL文字を含み本文と衝突しない）で一旦切り出し、出力時に [※挿絵N] に再変換
# 実装済み: IMAGE_PLACEHOLDER_TMP = "\x00IMG{}\x00"
```

### Pitfall 2: 段落区切りの正規化忘れ

`novel/*.md` 内の見出し除去で直前段落の末尾改行が孤立し、「意図しない空行2行」になる。全変換後に `\n{3,}` → `\n\n` で統一する。`--verify` で差分が出続ける原因第一位。

### Pitfall 3: novel/*.md 側に独自ルビ記法が残っている

`--verify` の比較時は両方を親文字に逆変換する（export 側＝pixiv記法、novel 側＝独自2形式）。片側だけだと誤差分になる。

### Pitfall 4: 本文中の `---`（HR）の素通り

変換パスではHRを除去しない。本文側の不要な `---` はフッターの `---` とは別物として残り、pixivプレビューで余計な水平線になる。ソース側で消す。`--verify` 側の比較ではHRは除去されるため、HRだけの差は検出されない。

### Pitfall 5: chNN.md の無見出しで `## 第N章　第N章` になる

見出しなし `ch01.md` のタイトル補完は `第1章` で、出力は `## 第1章　第1章` の重複になる。スクリプト側に `--zero-based` のような調整フラグはない。本文先頭H1の運用（本書「ファイル名の規約」）で潰す。旧式 `00-プロローグ.md` は `## 第0章　プロローグ` の0始まりになる点も同じく運用で吸収する。

### Pitfall 6: 挿絵カウントの「ずれ」

本文に画像タグがないのに挿絵を想定していると、プレースホルダーが期待より少なくなる。**画像挿入位置は必ず本文に記載する**（`![...](...)` か `<!-- 挿絵: シーン説明 -->`）。章ごとの想定挿絵数は `--check-length` のプレースホルダー数で照合する。

### Pitfall 7（環境）: `rm -rf` を含む cleanup コマンド

テスト用一時ディレクトリの削除に `rm -rf` を使うと、git-bash 環境では確認プロンプトで timed out になる場合がある。`%TEMP%` 配下の残置は無害なことが多いため、無理に消さない。
