# キャラ発想ガイド

`character-template.md`は記入欄の一覧である。上から順に埋めると平板になる。
本ガイドは発想の手順を示す。埋めた結果、その人物の一人称の声が安定し、次の行動が予測できれば完成である。

planning-workflow §3に入る前に本ガイドを読む。テンプレートを埋める前に**名前の候補だけ先に出す**（読みの仮決め）。名前が決まると人物が動き出すことがあるためだ。詳細はplanning-workflow §3の手順に従う。

## 0. 人物は三層でできている

身体の層、社会の層、心理の層の三つでできている。

- 身体の層：性別・年齢・体格・外見 → `[basic]` `[appearance]`
- 社会の層：職業・所属・家族・土地・関係 → `role` `[basic].affiliation` `[[relations]]`。世界観TOMLと整合させる
- 心理の層：性格・欲望・信念・恐れ → `[personality]` `[motivation]`

「薄い」「類型的」と感じる人物は、どれかの層が空である。心理の層は独立に書かない。「短気」と書く前に、原因が上の二層にあるか確認する。なければ上の層に足す。

## 1. 欠点を先に決める

長所から作ると好かれない。有能さ八割、欠点二割で作り、欠点を先に決める。

- 欠点は致命的でなくてよい。ただし作中で一度は判断を誤らせる。これを`flaw`に書く。`[personality].weaknesses`は性格傾向、`flaw`は物語装置として区別する。`flaw`/`quirk`/`heat`/`false_belief`は`lead`必須・`support`1件まで任意・`minor`禁止。端役の深みはTOMLに書かず発想の手順に留める
- 懸命に努力する人物、特に懸命に嘘をつく人物は好かれる
- 敵対者は悪いだけでなく、どこか愚かであると憎まれすぎない。敵対者の`strengths`を空にしない

## 2. 状況から職業と性格を逆算する

世界観と状況が先にあるなら「この状況に巻き込まれ続けるには、どんな職業と性格が必要か」を問う。

- 逆算の結果は`role`と`[basic].affiliation`に、そう動く根拠は`[motivation].principle`に書く
- 固定イメージに一つの反転を加えれば十分である

## 3. 属性ではなく人品を書く

学者なら部屋に文献がある、は属性である。そこに漫画が二冊ある、と書けるのが人品である。

- 職業から連想される標準装備ではなく、その人物だけのズレを`quirk`に一つ書く。「〜のとき、〜する」の条件形で書く。無条件形（何でも〜、必ず〜）は弱い LLM が毎回発動と読んで儀式化する
- この人物が必死になる対象を一つ決め、`heat`に書く。各章に一度その場面を用意できれば、その人物は動いている

## 4. 履歴書と日記を書いて捨てる

`core_wound` `desire_hidden` `false_belief`は、履歴書と日記を書いた後に要約する。

- 履歴書：兄弟構成、出身、学歴、なぜ今の土地に来たか。他者への態度。TOMLには書かない。書いて捨てる
- 日記：物語中の重要な三日を、その人物の一人称で書く。「あの時こう思っていたのか」が見えたら`[[foreshadowing]]`に回す
- 誤った信念：本人は正しいと信じているが物語中で崩される考え。過去のある瞬間には実際に正しかったからこそ信じている。それを`[motivation].false_belief`に一行で書く。場面の書き出し自体はTOMLに残さない。残すのは要約一行だけだ

読者に見えるのは島だけでよい。書いたことで`first_person`と`speech_style`の根拠ができればよい。

## 5. 配置：三人組、対照人物、部外者

- 一対一では「どちらが正しいか」の判定に収束し、話が転がらない。主要人物が二人しかいない企画は三人目を検討する
- 主人公と同じ状況で逆の原理で動く人物を一人置く。`[[relations]].function = "contrast"`
- 集団ものでは部外者を一人入れる。集団の異常さは部外者の目を通して初めて見える。`[[relations]].function = "outsider"`
- `kind`（学友・兄弟など関係名）と`function`（作劇上の役割）は別キーである。混ぜない。例：`kind = "弟"`かつ`function = "contrast"`
- 脇役は一つの特徴だけで十分である。`[design].screen_time`で`lead`/`support`/`minor`を明示し、端役に深みを足していないか確認する。packはこの値を見出しに添えて出力する

## 6. 敵対者の設計

- 敵対する側の総和は主人公より強くなければならない。開始時点で主人公は負け犬であるべきだ
- 主人公と敵対者は妥協できない何かで縛られている。縛りがなければ話し合いで終わる。`[[relations]].no_compromise`に理由を一行で書く
- 敵対者にも自分の物語がある。物語開始前から進行している目的を`goal_external`に書く

## 7. 設計後の自己点検

執筆前に一度、全章執筆後にもう一度回す。後者はrevision-workflow Phase CのC-2で行う。

| # | 問い | 見る場所 |
|---|---|---|
| 1 | 三層のうち空の層はないか | `[basic]` `[appearance]` `[[relations]]` `[motivation]` |
| 2 | 欠点は作中で一度は判断を誤らせる予定か | `flaw`とplotのscenes |
| 3 | その人物だけのズレがあるか | `quirk` |
| 4 | 必死になる対象があり、各章に一度は場面があるか | `heat`とplot |
| 5 | 主要人物どうしで似すぎの二人はいないか。いれば統合か削除 | `[personality].keywords`の重なり |
| 6 | 主人公が最も多面的か。端役に一特徴以上の深みを与えていないか | `screen_time` |
| 7 | 表と裏が反転しているか | `front`と`back` |
| 8 | 敵対者の総和は主人公より強いか。縛りはあるか | `no_compromise` |
